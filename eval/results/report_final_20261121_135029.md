### Model & Retrieval Configuration
- **Configured Groq Main Model (`GROQ_MODEL_MAIN`)**: `openai/gpt-oss-120b`
- **Configured Groq Fast Model (`GROQ_MODEL_FAST`)**: `openai/gpt-oss-120b`

- **Vector Store**: ChromaDB collection `academic_papers` in isolated `eval/data/chroma`
- **Chunking Configuration**: 800 tokens chunk size, 100 tokens overlap
- **Relevance Threshold**: 0.25 (cheap pre-filter applied only in Agentic workflow)

### Architectural Differences
- **Traditional RAG Baseline**: Single-pass procedure. Sends raw query directly to Chroma; retrieves top-5 chunks without relevance threshold filtering; passes chunks to a single `GROQ_MODEL_MAIN` call using `QA_SYSTEM_PROMPT`; performs no query rewrites, no routing, and no citation stripping.
- **Agentic RAG**: Multi-node LangGraph state machine. Query is routed by `router_node` (`GROQ_MODEL_FAST`) to produce a standalone query; `qa_retrieve` filters retrieved chunks at threshold >= 0.25; if empty or refused, loops through `rewrite_query` (up to 1 retry); `qa_answer` calls `GROQ_MODEL_MAIN`; post-processes citations via deterministic regex matching and strips unverified citations.

2. **Question A2 (Attention Is All You Need En-Fr BLEU — Discrepancy Reporting)**:
   - *Ground Truth Requirement*: Section 6.1 text states `41.0`, while Table 2 lists `41.8`. Both required.
   - *Baseline Outcome*: **PASSED (Score 1.00)**. Reported both 41.0 and 41.8.
   - *Agentic Outcome*: **FAILED (Score 0.50)**. Reported only 41.8 from Table 2.
3. **Question C7 (GridTCN Ablation Study — Agentic False Refusal)**:
   - *Question*: `Which component matters most in the ablation study?`
   - *Ground Truth Requirement*: Multi-scale dilated convolutions / temporal connections (Section 4.3).
   - *Baseline Outcome*: **PASSED (Score 1.00)**. Naive top-5 retrieval captured Section 4.3 chunks.
   - *Agentic Outcome*: **FAILED (Score 0.00 — False Refusal)**. Initial retrieval similarity fell below threshold 0.25; rewrite loop also fell below threshold, terminating at `qa_refuse` (`false_refusal: True`).
4. **Question C6 (GridTCN Training Duration and Hardware — Partial Answer vs. False Refusal)**:
   - *Question*: `How long did training take and on what hardware?`
   - *Ground Truth Requirement*: `3.5` hours on an 8-core `CPU` (from Section 3.3).
   - *Baseline Outcome*: **FAILED (Score 0.00 — False Refusal)**. Naive top-5 semantic search missed Section 3.3; LLM produced a false refusal (`'The paper does not appear to cover this topic'`).
   - *Agentic Outcome*: **PARTIAL PASS (Score 0.50)**. NOT a refusal (`refused: False`, `false_refusal: False`). The system generated an inference timing answer: `"The paper provides timing information for inference... GridTCN produces a 24-hour forecast in about 6 ms on a single CPU core... [5 Results, pp. 2-3]"`. This matched the `CPU` requirement (earning 0.50 credit), but failed strict correctness because it retrieved Section 5 inference timing rather than Section 3.3 training duration (`3.5 hours`).
5. **Scientific Notation & Unicode Formatting False Negatives (B2 & C3)**:
   - In **B2** (*LeafScan learning rate*), both systems outputted `1 × 10⁻³` using Unicode superscript `⁻³` instead of ASCII `1e-3` / `0.001` / `10^-3`. Both systems matched batch size `64`, receiving strict partial scores of 0.50.

   - *Evaluation Implication*: The models knew the factual answer, but strict regex string matching penalized typographic scientific notation formatting.
6. **Qualitative Verification of B3 (LeafScan Dataset Split)**:

## F. Evaluation Limitations
1. **Corpus and Dataset Scale**: Exactly 30 questions across 3 papers (10 per paper). While highly curated, statistical generalization across arbitrary academic papers is constrained.
2. **Shared Model Identity**: Both `GROQ_MODEL_MAIN` and `GROQ_MODEL_FAST` are configured to `openai/gpt-oss-120b` in runtime `.env`. In production with a smaller fast model (e.g. `openai/gpt-oss-20b` or 8B model), router latency would drop significantly.
3. **Strict Regex Token Matching**: Strict match criteria penalize valid mathematical formatting (such as Unicode `1 × 10⁻³` vs ASCII `1e-3`), leading to artificial penalties on questions B2 and C3.
4. **Rate Limit Sensitivity & Infrastructure Overheads**: Benchmark execution on the Groq free tier encountered a 200,000 Tokens-Per-Day limit during initial Stage 2 testing, requiring controlled resumption. Measured turn latencies include API queue wait times.
5. **Citation Reference Validity vs. Semantic Entailment**: Automated citation metrics confirm that cited section names and page bounds match retrieved chunk metadata; they do not verify full formal semantic NLI entailment.

## G. Final Conclusion
1. **Strict Accuracy Parity**: Both Traditional Baseline RAG and the Agentic Workflow achieved **identical overall strict correctness of 25 / 30 (83.3%)** and **identical answerable strict accuracy of 16 / 21 (76.2%)**.
2. **Partial Accuracy Parity**: Both systems achieved an identical mean partial factual score of **90.6% (27.17 / 30)**. Agentic scored higher on C1 (recovering dual numbers) and C6 (identifying CPU hardware), while Baseline scored higher on A2 (dual BLEU numbers) and C7 (ablation study).
3. **Refusal Reliability**: Both systems demonstrated **100% true refusal recall (9/9)** on out-of-scope and unanswerable questions. Each had exactly one false refusal (Question C6 in Baseline; Question C7 in Agentic).
4. **Citation Reference Validity**: Baseline achieved **100.0% (35/35)** valid chunk citations; Agentic achieved **96.4% (27/28)** valid citations (1 citation had page bound mismatch). Citation checking verified metadata alignment but not formal NLI semantic entailment.
5. **Cost & Latency Overhead**: The Agentic workflow introduced significant overhead for single-turn QA: **78 completed LLM calls** vs. **30 LLM calls** (**2.60x call multiplier**) and a mean latency of **22.37 seconds** vs. **14.03 seconds** (**1.59x latency multiplier**).
6. **Task-Specific Utility**: While Agentic RAG provides no factual accuracy advantage for simple single-turn factual questions, it provides decisive practical advantages in multi-step workflows: disk-backed caching provides a **66.8x speedup** on repeated study notes (2.71s vs 181.12s) and a **3.0x speedup** on slide outlines (3.84s vs 11.47s), while conversational routing handles follow-up rephrasings and off-topic filtering seamlessly.
